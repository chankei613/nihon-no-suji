## ✅ 確認できたもの

### 気象庁 AMeDAS 実況JSON（#1,#2,#5 の補助 / 他の多数の数字にも効く）

- 地点マスタ: `https://www.jma.go.jp/bosai/amedas/const/amedastable.json`
  - 200 / 約183KB / 全アメダス地点の番号・名称（漢字・カナ・英）・緯度経度・標高
- 最新時刻: `https://www.jma.go.jp/bosai/amedas/data/latest_time.txt` → `2026-09-02T04:20:00+09:00`
- 実況値: `https://www.jma.go.jp/bosai/amedas/data/map/{YYYYMMDDHHMMSS}.json`
  - 200 / 約250KB / 10分ごと
  - **1ファイルに全地点の temp / humidity / precipitation10m/1h/3h/24h / wind / sun / snow が入っている**
- 利用条件: 非公式（サイト内部データ）。政府標準利用規約準拠との気象庁見解あり。**仕様変更リスクは残る**。
- 使いどころ: 「今この瞬間の全国最高気温」「24時間降水量の最大地点」などリアルタイム集計。ただし**その日の確定最高/最低**はランキングCSV（下記）の方が正確。

### 気象庁「最新の気象データ」ランキングCSV（#1,#2,#5 の本命）

| 数字 | URL | サイズ |
|---|---|---|
| 日最高気温 | `https://www.data.jma.go.jp/stats/data/mdrr/tem_rct/alltable/mxtemsadext00_rct.csv` | 約124KB |
| 日最低気温 | `https://www.data.jma.go.jp/stats/data/mdrr/tem_rct/alltable/mntemsadext00_rct.csv` | 約124KB |
| 24時間降水量 | `https://www.data.jma.go.jp/stats/data/mdrr/pre_rct/alltable/pre24h00_rct.csv` | 約146KB |
| 1時間降水量 | `https://www.data.jma.go.jp/stats/data/mdrr/pre_rct/alltable/pre1h00_rct.csv` | 約143KB |

- 文字コード: **Shift_JIS**。更新: 毎時25分ごろ（10分間隔で更新の系統もあり）。
- 全観測所が1行ずつ。カラムに以下が最初から入っている（＝前日比計算を自前でやらなくてよい部分がある）：
  - 現在時刻、当日の最高気温（℃）、起時、**平年差（℃）**、**前日差（℃）**、極値更新フラグ、今年最高フラグ、今年の最高気温と観測日、**観測史上1位の値と観測日**、その月の1位、統計開始年
- これは企画書 §17「今年最高」「久しぶり」「平年より◯%」のような将来コンテンツにもそのまま使える。**MVP時点から履歴を貯めなくても"今年最高"が言える**のは大きい。
- 風速・積雪の同系CSVも存在（`https://www.data.jma.go.jp/stats/data/mdrr/wind_rct/...` / `snc_rct`）→ 季節カードで利用。

### 東京電力パワーグリッド でんき予報CSV（#6）

- 当日: `https://www.tepco.co.jp/forecast/html/images/juyo-s1-j.csv`
- 翌々日: `https://www.tepco.co.jp/forecast/html/images/juyo-s2-j.csv`
- 200 / 約15KB / Shift_JIS / **約5分ごと更新**（先頭行に `2026/9/2 4:25 UPDATE`）
- 中身: ピーク時供給力・時間帯・**予備率(%)**・**使用率(%)**、予想最大電力、当日実績（5分間隔値, 万kW）
- 旧 `juyo-j.csv` `juyo-YYYY.csv` は**廃止/更新停止**（`juyo-2025.csv` は 2025/7/22 で停止）。**現行は `juyo-s1-j.csv`**。
- 他エリア（北海道・東北・中部…）も各送配電会社が同種CSVを出すが**パス・カラムがバラバラ**。10エリア対応は Phase 5。まず東京エリアで成立させる。

### P2P地震情報 API（#8）

- `https://api.p2pquake.net/v2/history?codes=551&limit=20`
- 200 / JSON / 認証不要 / 地震ごとに `earthquake.time` `hypocenter`（名称・緯度経度・深さ・M）`maxScale`（震度×10: 20=震度2）`points`（市区町村ごとの震度）
- 元データは気象庁。「過去24時間の震度1以上の回数」= `time` でフィルタしてカウント。「今年の震度3以上」= `maxScale>=30` を集計。
- WebSocket版もあり（リアルタイム通知に使える）。

### 東京の日の入り時刻（#7）

- 外部依存なしで確定可能。NOAA の日出没アルゴリズム（または `SunCalc` 相当）を実装。東京 = 北緯35.6762 東経139.6503。
- 検証用の突き合わせ先: 国立天文台 暦計算室 `https://eco.mtk.nao.ac.jp/cgi-bin/koyomi/sunmoon.cgi`（各地のこよみ）。
- 「昨日より1分早い」= 前日の計算値との差。**Collector不要、純粋な計算メトリック**。月齢（#31）も同じ扱いで同時に入れられる。

## ⚠️ 課題があるもの（v0.1のクリティカルパス）

### #3 主要ダム貯水率（全国平均）

- **統一APIは存在しない。** `www.river.go.jp/kawabou/`（川の防災情報）はSPAで、`/kawabou/api/...` 風のパスも実体はHTMLフォールバック（クリーンなJSONは出てこない）。
- 実データがある場所:
  - 近畿地方整備局「琵琶湖水位・ダム貯水率」`https://www.kkr.mlit.go.jp/river/biwakosuiidamutyosuiritsu.html` — HTML表。**土日祝を除く**更新。
  - 関東地方整備局「首都圏の水資源状況（リアルタイム）」`https://www.ktr.mlit.go.jp/river/shihon/river_shihon00000226.html`
  - 水資源機構 各水系局の水源情報ページ（利根川・筑後川など個別）
  - 水文水質データベース `http://www1.river.go.jp/`（後述の制約あり）
- 対応方針:
  1. 「主要ダム」を**明示的に定義する**（例: 利根川水系上流8ダム ＋ 淀川水系 ＋ 筑後川水系 の計N基、または関東地整の「首都圏水がめ」9ダム）。
  2. 各地整のHTML表をパースする Collector を1つ書く（整備局ごとにパーサ）。
  3. **平日更新なので、UI側で「◯月◯日時点」表記＋週末は据え置き表示**（企画書 §4「前回発表比」の考え方を流用）。
- 難易度: **高**。ただし「関東地整の首都圏水がめ1ページだけ」に割り切れば中で収まる。**MVPは関東（首都圏水がめ貯水率）から始めるのを推奨。**

### #4 琵琶湖水位

- 水文水質DB `http://www1.river.go.jp/cgi-bin/DspWaterData.exe?KIND=9&ID=306041286603280`:
  - User-Agent がブラウザでないと **403**。ブラウザUAでも今回は本文がほぼ空（フレーム/セッション依存の可能性）。
  - 履歴の一括DLは可能だが**多段フロー**（検索フォーム→データURL生成→DL）。日次バッチには実装可能だが手間。
- より簡単な代替:
  - 近畿地整「琵琶湖水位・ダム貯水率」ページ（#3と同じページに水位も載る）
  - 滋賀県「琵琶湖の水位情報」`https://www.pref.shiga.lg.jp/ippan/kendoseibi/kasenkoan/332467.html`
  - 国交省 琵琶湖河川事務所 `https://www.kkr.mlit.go.jp/biwako/bousai/suii.html`（10分更新の速報値）
- 対応方針: 琵琶湖河川事務所の速報ページ or 近畿地整ページをスクレイピング。**#3と同じCollectorにまとめられる**（同一ページに両方ある）。
- 難易度: **中〜高**。

### e-Stat（#83 訪日外国人・#87、Phase 4以降の月次群）

- API v3.0 は appId 登録必須。**未取得のため今回は未検証。**

## 実装への示唆

1. **Collector は「気象庁ランキングCSV」から着手**するのが最短（#1,#2,#5 が1つのパーサ系で片付く。Shift_JIS→UTF-8変換、指定カラム抽出だけ）。
2. **AMeDAS map.json を1日数回保存しておく**と、後から多数の「地点数系」数字（猛暑日地点数・積雪地点数など #4〜#8,#21）を履歴から作れる。取得は1エンドポイントなので今すぐ始める価値あり。
3. **ダム/琵琶湖のスクレイパは"関東地整＋近畿地整の2ページ"に限定**して1本のCollectorに。全国網羅は Phase 5。
4. 日の入り・月齢・今年の残り日数（#28,#29,#30,#31,#111）は **Collector不要の計算メトリック**として別レーンで実装 → v0.1のカード数を水増しできて体験が厚くなる。
5. `metric_values` には気象庁CSVの「平年差・前日差・今年最高・観測史上1位」も一緒に保存する（`metadata` JSONカラム）。将来コンテンツの前借り。
6. すべての外部取得に**ブラウザUA固定＋タイムアウト＋失敗時リトライ＋前回値フォールバック**を最初から入れる（気象庁非公式・地整HTMLは落ちる前提）。
